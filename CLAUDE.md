# CLAUDE.md: Agri-DSS (AI-Powered Agriculture Decision Support System)

Final-year B.Tech project. A MERN app + Python ML service + Gemini 2.5 Flash orchestration, for Indian farmers in 5 languages (en, hi, te, ta, kn).
**Read `PROGRESS.md` first.** It has the current phase, what's done, what's pending, and the next steps.
The full original spec is in `docs/SPEC.md`. Follow it phase by phase.

## Working rules (from the user)
- Work **phase by phase**. At the end of each phase, run the verification, show the results, then **wait for the user's OK** before starting the next phase.
- **Ask before** downloading datasets or installing anything global. Installs inside `node_modules` / `ml-service/.venv` are fine.
- After each phase, give a short summary: what was built, how to run it, and what's left. Then update `PROGRESS.md`.
- Never commit `.env`, datasets or model binaries (see `.gitignore`). No hard-coded secrets or URLs: all config comes from env.
- Every ML response includes `model_version` + confidence values. Medical/chemical advice always carries a safety disclaimer.
- Keep Gemini calls minimal (free tier): short context, no extra calls, caching.

## Environment (Windows 11)
- `python` is NOT on PATH. Use `py -3.11` to create venvs and `ml-service/.venv/Scripts/python.exe` for everything else.
- Node 26, npm 11. Shells: PowerShell (primary) and Git Bash.
- The machine has hit **low memory** before, and a background pip install was killed. Avoid running heavy jobs in parallel.
- PyPI downloads are flaky. Use `pip install --default-timeout=60 --retries 10`.
- **Stopping servers:** bash `taskkill` with escaped `$_` silently fails. A stale server keeps the port and new launches die with EADDRINUSE, so you end up testing OLD code. Always stop servers with the PowerShell tool: `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | ? { $_.CommandLine -match 'src.index\.js' } | % { Stop-Process -Id $_.ProcessId -Force }` (and the same for python/uvicorn), then check `uptimeSec` in `/api/health` after a restart.
- Vite listens on `localhost` (IPv6), not 127.0.0.1.
- **Port 8000 can be taken by another of the user's apps ("scholar-backend").** `npm run health` then shows the wrong service as OK. Don't kill it. `start.bat` moves our ML service to 8001 by itself; `npm run health` then needs `ML_URL=http://127.0.0.1:8001/health`.
- **Gemini free tier** is tiny (gemini-3.5-flash: 20 requests/day/model; quotas are per model). Don't burn requests on ad-hoc probes. The `[chat]` warn log shows the quotaId on 429.

## Layout and ports
| Dir | Stack | Port | Health |
|---|---|---|---|
| `client/` | React 18, Vite 8, Tailwind v4 (`@tailwindcss/vite`), react-router 7, react-i18next, axios, recharts | 5173 | `/status` page |

- **`start.bat` / `npm start` (`scripts/start-all.js`)** is the normal way to run everything: preflight checks, a port held by a foreign app moves our service to the next free port (passed on via env `ML_PORT`, `ML_SERVICE_URL`, `PORT`, `VITE_DEV_PORT`, `VITE_DEV_PROXY_TARGET`), an already-running Agri-DSS is only stopped with `--restart` (it never closes a shell), waits for health and prints the URLs. Stopping the launcher stops all children. Root `npm run dev` still starts all 3 without the checks (concurrently; the ML service is launched by `scripts/run-ml.js`, which takes `ML_PORT` from the env first). `npm run health` pings them all.
- The Vite dev server proxies `/api` → server. Server → ML calls carry the `X-Internal-Key` header (`server ML_INTERNAL_KEY` == `ml-service INTERNAL_API_KEY`).
- Local `.env` files exist. `server/.env` has the user's real `MONGODB_URI` (Atlas) and `GEMINI_API_KEY`. Never print them.

## Key code locations
- ML models load once at startup in `ml-service/app/services/registry.py`. A missing artifact disables only that feature, and `/health` reports `degraded`.
- Crop training logic (single source of truth): `ml-service/training/crop_training.py`. Charts: `training/charts.py`. CLI: `py -m training.train_crop` (run from `ml-service/`). Notebook 02 imports the same module.
- Composite crop score: `ml-service/app/services/crop.py`, `final = 0.6·prob + 0.2·season + 0.2·weather`.
  - `season_score`: 1.0 if the crop is in the current season, 0.5 if it's in the **upcoming** season (the chosen meaning of "adjacent", since with 3 seasons every season borders the other two), 0 otherwise. Data: `knowledge/crop_seasons.json`.
  - `weather_score`: per variable, 1.0 within ±1 std of the crop mean, falling linearly to 0 at ±3 std; averaged over temperature, humidity and rainfall (`knowledge/crop_profiles.json`, generated by training).
  - Rainfall uses the dataset's scale (≈ mm per month or growing period, not mm/day). The server must convert forecast rainfall before calling.
- **Location-based recommendation (Phase 6.5):** `server/src/services/locationRecommend.js` (soil: manual > the field's own tests, recency-weighted with a 365-day half-life plus a least-squares trend > district estimate from ML `GET /soil/district`; climate: `services/climate.js` 10-year monthly normals from the Open-Meteo archive, cached 7 days per ~11 km cell, with live weather as fallback; rotation from `CropHistory`; area = other users' crops within `AREA_RADIUS_KM`, **same season only**). Routes: `/api/fields` (+ `/:id/soil-tests`, `/:id/crops`), `POST /api/recommend/location`. Chat tool `recommendCropForLocation`; basic mode uses it when the message has no soil numbers.
  - ML: optional `context` on `/predict/crop` adds `rotation_score` (`knowledge/crop_families.json`) and `area_score` (needs ≥5 records). Each active extra takes 0.1 and the base weights scale down proportionally (both active: 0.48/0.16/0.16/0.1/0.1). **No context = exactly the original formula.**
  - District soil: `training/build_district_soil.py` builds `knowledge/district_soil.json` + `district_boundaries.json` (gitignored; source = SHC via Esri India Living Atlas). SHC Low/Med/High shares → training-data quantiles 1/6, 1/2, 5/6; pH classes → 6/7/8. ML `/soil/district` takes lat/lon (point-in-polygon, `app/services/soil.py`) or a name.
  - Season order for history: Zaid (Mar) < Kharif (Jun) < Rabi (Nov) within a calendar year; `year` = the year sown.
- **Address autofill:** `server/src/services/places.js` + `/api/places/search|reverse|pincode/:pin` (no auth, own 60/min limiter, cached). Photon for type-ahead (has mandal/taluk + PIN but rarely the district), Nominatim reverse for the district (`state_district`; Nominatim forbids type-ahead, so it is only called on pick / geolocation, throttled to 1 req/s), India Post for PINs (no coordinates: the client verifies a post office by same PIN, then same state, else uses the district centre and flags `approximate`). Client: `components/PlaceSearch.jsx` (combobox) inside `LocationPicker`; location objects carry village, subDistrict, district, state, pincode (on User.location and Field). The profile district/state also feed the district-soil fallback. OSM attribution is shown under the picker (required).
- Chart styling: validated categorical palette slots `#2a78d6`, `#eb6834`, `#1baf7a`, then `#eda100`, `#e87ba4` for rotation/area (the 5-slot set passes the validator); text in neutral inks; dot plot (not truncated bars) for model comparison.

## Commands
- **New PC / sharing:** `setup.bat` (`scripts/setup.js`) builds the venv (pins from `ml-service/constraints.txt`, rebuilds a venv copied from another PC), npm installs, creates `.env`s. `npm run pack` makes a clean share zip (no venv/node_modules/data/.env). Regenerate `constraints.txt` with `pip freeze` after changing Python packages.
```bash
# ML tests
cd ml-service && .venv/Scripts/python.exe -m pytest -q
# Server tests (node:test + supertest)
cd server && npm test
# Retrain crop models (several minutes, CPU heavy)
cd ml-service && .venv/Scripts/python.exe -m training.train_crop
# Train the disease model on CPU (needs data/plantvillage/; ~30 min first run, then ~1 min from the feature cache; uses ~7 GB RAM)
cd ml-service && .venv/Scripts/python.exe -m training.train_disease --data data/plantvillage
# Execute a notebook headless (from notebooks/)
../ml-service/.venv/Scripts/python.exe -c "import nbformat;from nbclient import NotebookClient as C;nb=nbformat.read('02_crop_models.ipynb',4);C(nb,timeout=3600,kernel_name='python3',resources={'metadata':{'path':'.'}}).execute();nbformat.write(nb,'02_crop_models.ipynb')"
```
